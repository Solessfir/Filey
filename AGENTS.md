# Filey

A functional reimplementation of a reference file manager ("the reference") in C23. `AppSpecification.md` is the authoritative design document; read the relevant sections before changing architecture, memory, strings, containers, UI, or build code.

## Goals

- Match the reference's behavior, feel, and performance. Binary-identical output, original symbol names, and internal layout are not goals.
- Windows comes first, to validate the reverse-engineered behavior side by side with the original.
- Linux is the real target. Never take a Windows-only shortcut in shared code that would make the Linux port harder.
- macOS is out of scope. Do not add macOS code, stubs, or `#ifdef`s.

## Reverse-engineering reference

Spec Section 1.2 describes how to run headless Ghidra MCP against the reference executable. Use it to verify behavior when the spec is silent or ambiguous. Treat decompiled output as evidence to confirm, not as source to transcribe.

The reference borrows heavily from the RAD Debugger, whose source is at https://github.com/EpicGamesExt/raddebugger (`src/raddbg/raddbg_core.c` for its panels, commands and animations, `src/ui/` for its UI layer). Look there for how a feature the reference lacks or shares with it might work, such as panel zoom.

Screenshots of the reference app, kept outside the repository, are the visual reference for UI appearance and layout. Inspect the relevant screenshots before implementing or changing UI.

`Source/Tools/Compare/Compare.py` runs the reference and Filey one after the other on a fixture folder, in the middle of the main screen without taking the focus, posts the same input to both, and saves matching screenshots and animation frames, so UI work can be measured against the original without screenshots from the user. Filey runs there with `FILEY_POSTED_POINTER=1`, so that the posted moves are not undone by Windows telling it the real pointer is elsewhere, and takes Shift, Ctrl and Alt from posted key messages rather than the real keyboard's state. `COMPARE_LOG=<file>` keeps what the apps write to stderr. `COMPARE_GRAB=1` takes Filey's animation frames off the screen as the reference's are, so that both are timed the same way. The reference gets `FakeInput.dll` (pointer, focus and held keys from shared memory), so the real pointer and keyboard are never used. Set `COMPARE_REFERENCE` to the reference executable and `COMPARE_REFERENCE_STATE` to its session and settings files, `;` separated, which it backs up and restores around every run. The reference set to its built-in dark scheme matches Filey's `theme = fullmoon`, which the Options' choices leave out. The display here is at 125%, so sizes measured in screenshots are divided by 1.25 before they go into the code as logical units.

## Architecture rules

- Layers are Base, Platform, Renderer, UI, and Program. Dependencies only point downward.
- OS APIs (Win32, COM, POSIX, X11/Wayland) live only in the platform layer. The renderer's graphics API lives only in its backend files.
- Memory is arena/lifetime based (permanent, frame, scratch, job, feature). Do not add per-object `malloc`/`free`.
- `{0}` must be a valid state for core types, including for the first mutation.
- Strings are UTF-8 `String { const char *value; u64 length; }` views. Convert to UTF-16 or null-terminated strings only at the platform boundary.
- UI is immediate-mode with keyed retained blocks. UI code only queues commands; never block or do I/O while building UI.
- Slow work (enumeration, file operations, thumbnails, indexing) runs in background jobs that get copied input and their own arena, with cooperative cancellation.
- Unity build through a direct build script. Do not introduce CMake, Meson, or similar for the developer build.
- Third-party code must be small, single-purpose, auditable, and kept under `Source/Lib/`.

## Code style

- C23 only. C++ is allowed only for a tiny, isolated platform adapter that has no reasonable C alternative (spec Section 54.1).
- `PascalCase` for types, functions, and macros. Layer prefixes are `UI_`, `R_`, `P_`, and `Prog_`. Use `camelCase` for fields, locals, and parameters.
- Enum values are `Type_Value` (e.g. `FileKind_Directory`), and dense enums end with a `_Count` sentinel.
- Use `function`, `global`, and `local_persist` instead of bare `static`.
- Use the base-layer vocabulary (`u64`, `b32`, `S("...")`, `ArenaPushStruct`, `ArrayPush`, `QueuePush`, etc.) instead of raw runtime calls.
- `S("...")` is a compound literal, which is not a constant in the initializer of `global` or `local_persist` data (GCC's `-Wpedantic` flags it). Write `SInit("...")` there; a function's table of macros that wrap `S()`, such as `Icon_*`, is left automatic instead.
- Prefer standard C23 (`__VA_OPT__`, `static_assert`, `alignof`) over compiler extensions.
- Use the base type aliases (`u8`..`u64`, `i32`, `f32`, `b32`, `wchar`, `rune`) instead of `int`, `float`, `unsigned`, `size_t`, `WCHAR`, etc., including in the C++ adapter. Internal helpers of a layer use a double underscore (`R__FontFindGlyph`, `GL__PushInstance`).
- Screenshots of the reference's original source, kept outside the repository, show its style (`result` return variables, `Prefix__Name` internals, `enum8(...)` fields, `_Count` sentinels). Use them as a loose reference, not a formatting rule.
- Do not edit generated files (`*.generated.h`, `Meta/*.meta.h`). Change the generator or its input instead.
- Text shown to the user is written `Tr("...")` (`TrF` for a format string, `TrInit` in `global` data, translated where drawn with `Prog_Tr`, `TrN(count, "one", "other")` for a counted format), which Codegen collects into `Meta/Strings.meta.h` for the language template, with the commands' labels and tooltips. A built-in language is a `Resources/Languages/<Name>.lang` file embedded in `Program.c`: each entry is the English line, then `= ` and its translation, a line break written `\n`; a counted text's forms are separated by ` | `, two for one and the rest, three for one, a few and many (Russian). Keep translatable strings free of leading and trailing spaces, which editors strip. A string made on a worker thread is written `TrMark("...")` and translated where it is shown. The build fails on a capitalized literal with a space in `Program/Program.c`, `Commands.c`, `Directory.c` or `Media.c` that is not translated; `NoTr("...")` (`NoTrF` for a format) keeps one as it is on purpose, as saved names.
- Commands and their default hotkeys are declared once in `Source/Program/Commands.txt`. Add a command there, then handle its `Prog_CommandKind_` case in `Prog_ProcessCommands`.
- The app icon is `Source/Resources/Filey.svg`. After changing it, run `python3 Source/Tools/IconBake.py` (needs `rsvg-convert`), which rewrites `Filey.ico` (linked into the Windows executable through `Filey.rc`) and the Linux theme sizes in `Resources/Icons/`; commit all of them. `Resources/filey-symbolic.svg` is the one-color version that panels recolor to their theme; keep its shapes in step with the master by hand.
- `Build.bat release install` replaces the copy Filey Setup installed in `%LOCALAPPDATA%\Filey` with the build, moving a running one aside; `./Build.sh install` installs a build for the current user (`~/.local/bin`, the desktop entry `Resources/filey.desktop` and the hicolor icons); `install.sh install` and `install.sh uninstall`, which the README runs through `curl`, do the same with the latest release's Linux build. Keep `README.md` in step with features and setup.
- UI icons are a Lucide subset (ISC) embedded with `#embed`. To add one, append its Lucide name to `Source/Lib/Lucide/Icons.txt` and run `python Source/Tools/LucideSubset.py <extracted lucide-static npm package>` (needs `fonttools`). It rewrites `Lucide.ttf`, its `LICENSE` and `Meta/Icons.meta.h` (`Icon_<Name>` strings drawn with the icon font); commit all of them. A name ending in `-filled`, such as `star-filled`, is that icon solid.

## Toolchain

- Clang with `-std=c23` on every platform. MSVC `cl` is not supported; on Windows `Build.bat` uses the Clang bundled with VS Build Tools plus the MSVC/SDK environment from `vcvars64.bat`, linking with lld. The DirectWrite rasterizer `Win/WinFontRasterizer.cpp` is the only C++ file; it is compiled separately with `-fno-exceptions -fno-rtti` and linked in through the C header `Win/WinFontRasterizer.h`.
- GCC is a secondary Linux compiler for catching portability issues (`CC=gcc ./Build.sh`).
- Static analysis uses `clang --analyze` (the `analyze` build flag) and `clang-tidy`. Do not use Cppcheck; it has no C23 support.
- Linux debug runs SHOULD use the `asan` flag (ASan + UBSan).
- Linux app dependencies: `wayland` (client, cursor, egl), `libxkbcommon`, EGL (`mesa`/`libglvnd`), `freetype2`, and `fontconfig`, found through `pkg-config`; `libarchive` is loaded at run time, for archives. The xdg-shell, fractional-scale and viewporter protocol code is generated and committed under `Source/Linux/Protocols/`, so `wayland-protocols` is needed only to regenerate it:
  `wayland-scanner client-header|private-code /usr/share/wayland-protocols/stable/xdg-shell/xdg-shell.xml Source/Linux/Protocols/XdgShell.generated.{h,c}`, and likewise `staging/fractional-scale/fractional-scale-v1.xml` to `FractionalScale.generated.{h,c}` and `stable/viewporter/viewporter.xml` to `Viewporter.generated.{h,c}`.
- The `profile` flag defines `PROFILE`, which turns `ProfileScope("Name") { ... }` (`Platform/Profile.h`) into timed scopes on any thread. On exit the app writes `Filey.trace.json` to the working directory; open it in https://ui.perfetto.dev. Without the flag the macros compile to nothing.
- `FILEY_VERSION=1.2.3` gives either build script the version the app shows, at the end of the main menu (a click copies it), and on Windows the executable's details. Without it, `git describe --tags --always --dirty` names the build: a `v` tag's version and the commits since it, `0.1.0+<commit>` while there is no tag, and 0.1.0 outside a repository. Pushing a tag such as `v1.2.3` runs `.github/workflows/release.yml`, which builds and tests on Windows and Linux with that version and publishes a GitHub release of `Filey-<version>-windows-x64.zip` and `filey-<version>-linux-x64.tar.gz`.
- `EXTRA_CFLAGS` adds ad-hoc defines to either build script. `-DLOG_EVENTS` prints every platform event to stderr.
- Bookmarks and recents are saved as `Bookmarks.conf` and `Recents.conf`, and the folders whose view the lock button keeps (zoom, order, folder sort, grouping and columns) as `FolderViews.conf`, the system menu commands pinned to the top as `MenuPins.conf`, the menu editor's hidden items and order of the system menus' top level (by label) as `MenuHidden.conf` and `MenuOrder.conf`, the palette's starred Quick commands as `QuickCommands.conf`, the kinds of notice muted with a card's bell (or by hand, errors too, by their names such as `undo.nothing` or `rename.failed`) as `MutedNotices.conf`, the saved layouts (Save Layout, Load Layout, and Load On Startup's custom choices) as `Layouts.conf`, the torrent downloads under way, five at once in slots of their own and the rest waiting in its order, each `.torrent` with the files ticked for it, as `Torrents.conf`, which a quit leaves for the next run to start again, the custom color schemes (`theme` and `theme.light` can name one) as a `<name>.scheme` file each, which Matugen can render from the wallpaper with `Resources/filey-matugen.conf`, applied again as it does, in `%APPDATA%\Filey` or `~/.config/filey`, and the panels (their columns, order and inspector view) and tabs as `Session.conf` on exit, which a start without folder arguments restores. The drive index is written to `%LOCALAPPDATA%\Filey` or `~/.cache/filey` as `Index.bin` while a walk of the drives runs (`Index.bin.walk`, moved over it once the walk is done), which starts, loading the last one to search meanwhile, the first time Go To searches it with Alt+E, as the reference searches only the drives, the places, the folders the system names, the recents, the bookmarks and its own settings files. `Settings.conf` there (the "Edit Settings File" command writes a commented template on first use, and the Options popup, Ctrl+Comma, sets its lines) holds `language` (English, a built-in language such as `Русский`, or a custom one, `<name>.lang` in the settings folder, which "Create Custom Language" writes from the shown language as a template; unset, the system's language when one is built in, by `P_SystemLanguage`), `scale`, `animations = false`, `theme` (a built-in scheme: `filey-dark`, Filey's own and the default, `catppuccin-frappe`, `catppuccin-latte`, which `light` names, and `nord`, `gruvbox`, `tokyo-night` and `one-dark`; `fullmoon`, the reference's built-in dark scheme, for side-by-side checks; or a custom scheme's name), `theme.system` (on by default: the system's light mode brings `theme.light`, its dark mode `theme`, read on Linux from the settings portal through `gdbus`, then GTK's settings, and on Windows followed as it changes), `theme.light`, `spacing`, `borders` (the outlines' thickness in pixels, 1, 1.5, 2, 2.5 or 3, by default 1, and the lines between areas in the nearest whole pixels), `corners`, `rows.alternate`, `inactive.opacity`, `font`, `inspector.font`, `inspector.fontSize`, `inspector.layout`, `inspector.highlight`, `files.extensions`, `files.hidden`, `files.system`, `paths.short`, `paths.trail`, `checkboxes`, `menus.inline`, `thumbnails`, `folders.size` (and `.ssd`, `.hdd`, `.network`), `notices` (all, warnings, errors or off: the least kind of notice shown in the window's corner), `notices.sidebar` (on by default: the notices and the progress cards at the bottom of the sidebar while it shows; off, or with the sidebar hidden, in the corner of the panel showing the folder a transfer goes into), `updates.check` (on by default: the main window asks GitHub's latest release through `curl` once a day, keeping the answer and the version offered last in `Update.conf` in the cache folder; a newer one gets a notice, a dot on the main menu's button and a menu item, whose Update downloads the release's archive into the run folder, puts its executable in place of the running one, `P_ReplaceExecutable` (on Windows the running one moves aside to `Filey.old.exe`, or `Filey.old-<pid>.exe` while an older one runs from that), and starts it with `--after=<pid>`, which waits for this process to quit and removes the copies moved aside; `FILEY_UPDATE_URL` points the check at another answer, as a `file://` one in tests), `git.fetch` (the shown folder's repository fetched at most every five minutes, so that its commits to pull are counted; git runs without asking for a sign-in), `archive.level` (how hard the archives Filey makes are compressed, 0 to 9), `video.codec` and `video.quality` (what Compress Video encodes to, hevc, h264 or av1, on the graphics card's NVENC, AMF or Quick Sync when it has one, and its constant quality, 0 to 51), `download.audio` (a pasted web address comes down as its sound alone, as MP3), `torrents.delete` (a torrent downloaded whole sends its `.torrent` to the bin; shown in Options only where aria2c is on the PATH), `audio.volume`, `recents.store`, `recents.highlight`, `recents.sort`, `startup`, `newtab`, `instances.single` (on by default: a later run hands its folders to the open window as new tabs and quits, found by a named mutex and window property on Windows and an abstract socket on Linux, one for each settings folder, so a run with its own `FILEY_CONFIG_DIR` gets a window of its own; New Window passes `--new-window` for one too, which leaves the session to the main window), `vsync`, the pointer's `click.*`, `hover.*` and `scroll.*`, `keys.character` (what a letter key does in the lists: filter, hotkey or select), `transparent`, `color.<theme field>`, `glass.window`, `glass.popup`, `glass.opacity`, `glass.popupOpacity`, `glass.blur` and `glass.backdrop` (the transparent theme's tints, the window tint's opacity where there is no backdrop to choose, the floating boxes' tint's opacity, how far its floating boxes blur what is under them, and what Windows draws behind the window) and `hotkey.<Command>` lines and applies on save. Manual test runs SHOULD set `FILEY_CONFIG_DIR` to a temp folder so that they leave the user's settings alone; the headless tests never load settings.
- A crash leaves a report in `Crashes` in the cache folder (`%LOCALAPPDATA%\Filey` or `~/.cache/filey`, or `FILEY_CONFIG_DIR`): a minidump on Windows, the stack as text on Linux. The next start marks it seen (`.seen` before its extension) and offers a notice whose Report on GitHub opens a new issue with the version and system filled in, the Linux stack too, and opens the folder with the report selected to attach. `FILEY_TEST_CRASH=1` crashes a debug build as it starts, to try it.
- `FILEY_CAPTURE_DIR=<folder>` writes every presented frame there as `frame.bmp`, or with `FILEY_CAPTURE_SEQUENCE=1` as `frame-<n>-<microseconds>.bmp`, so that screenshots and animation timings can be taken with the window off-screen.
- WSLg provides a Wayland compositor, so the Linux window path can be run from WSL (software GL there).
- Both build scripts first compile and run `Source/Tools/Codegen.c`, which regenerates `Source/Meta/*.meta.h` (committed) and fails the build on malformed input.
- Output goes to `Bin/<debug|release>/`. The unity root is `Source/Unity.c`; base-layer tests are a second unity root, `Source/Tests/Tests.c`, built and run by the `test` flag.

```text
Build.bat [release] [analyze] [profile] [test] [install]  Windows
./Build.sh [release] [analyze] [asan] [profile] [test]    Linux / WSL
```

## Source layout

```text
Source/
├─ Base/       Base.h + Base.c: types, asserts, arenas, pools, lists, strings, arrays, maps
├─ Platform/   Platform.h + PlatformEvents.c: window/input contract; Jobs.h + PlatformJobs.c: worker queue; Files.h: filesystem contract; Profile.h + PlatformProfile.c: scope profiler; PlatformArchive.c: reading and writing archives with libarchive, which each platform's files include after giving it the library and the file system
├─ Win/        WinPlatform.c (memory, time), WinWindow.c (Win32 window, input, WGL, clipboard), WinFont.c + WinFontRasterizer.cpp (DirectWrite glyphs), WinThreads.c + WinFiles.c (listing, watching, file operations through the shell, archives through the system's `archiveint.dll`), WinIcons.c (shell image-list file icons, type names), WinShell.c (shell context menus, drag and drop, dragging out of archives through the shell's archive folders, and installing for the user: the copy, its shortcuts, its Apps & features entry, the PATH, Set as default and the right-click entries), WinAudio.c (sound out through waveOut), WinLaunch.c (opening files; WinRT launcher with neighboring files for packaged apps; the system's PDF renderer, for the inspector's first page of a PDF)
├─ Linux/      LinuxPlatform.c (memory, time), LinuxWindow.c (Wayland window, input, EGL, clipboard, drag and drop), LinuxFont.c (fontconfig + FreeType glyphs), LinuxThreads.c + LinuxFiles.c (listing, watching, launching, file operations, freedesktop trash and archives through a loaded libarchive), LinuxIcons.c (freedesktop icon theme file icons, and thumbnails from the installed thumbnailers through the shared thumbnail cache), LinuxAudio.c (sound out through PulseAudio's simple API, loaded at run time, which PipeWire serves too), LinuxApps.c (desktop entries and mimeapps.list for Open With, Open in Terminal, Filey's own context menu)
├─ Renderer/   Renderer.h contract; OpenGLRenderer.c backend; Font.c glyphs drawn as text first needs them, into atlas pages, from the platform's font face, which takes a character the font lacks from a system font that has it (DirectWrite's font fallback, fontconfig), and text
├─ UI/         UI.h + UI.c: keyed blocks, layout, input and rendering
├─ Program/    Program.h + Directory.c: browser state and background results; Commands.txt + Commands.c: command table and deferred actions; Icons.c: file icon cache and atlas; Models.c: 3D model readers (OBJ, STL, PLY, glTF, binary FBX, .blend, binary USD and .usdz), with their materials' colors and pictures and their vertex colors, whose meshes the inspector draws on the GPU (`R_MeshDraw`), turned by dragging, and the icon views' thumbnails in software; Office.c: the text of Word documents and spreadsheets, read from their zip of XML; Media.c: audio and video through the FFmpeg tools on the PATH (ffprobe's details, an audio file's waveform, decoded by ffmpeg and played from the inspector's toolbar through the platform's sound (`P_AudioOpen`) at a volume that changes as it plays, and a video's frame for the inspector, Compress Video, a web address pasted into a folder downloaded with yt-dlp, and torrents: a magnet link or a .torrent's web address pasted fetches the .torrent into the folder (`Prog_FetchTorrent`), whose files the inspector lists to be ticked (`Prog_ReadTorrent`), and its Download button, Download Torrent, or opening a .torrent when no program is set to open torrents downloads the ticked ones with aria2c without seeding, all run through `P_RunCommandStream` in a transfer card); Blp.c: Blizzard's BLP textures (BLP1 and BLP2: paletted, DXT1/3/5, BGRA and JPEG), for the inspector, the icon views' thumbnails and the models' pictures; Program.c: UI
├─ Meta/       generated tables (Commands.meta.h), icon codepoints (Icons.meta.h) and the translatable strings (Strings.meta.h)
├─ Lib/        third-party code and assets: Lucide icon font subset, stb_image (PNG, JPEG, GIF, BMP, TGA, PSD, HDR, PNM on Linux; on Windows TGA and PSD, which WIC has no codec for, and its zlib decoder, for FBX arrays and zip files), stb_image_write (PNG, for the Linux thumbnail cache), nanosvg (SVG, Linux icons), the zstd educational decoder (compressed .blend files)
├─ Resources/  app icon (Filey.svg master, generated Filey.ico and Icons/ sizes), Filey.rc for the Windows executable, filey.desktop, filey-matugen.conf (the Matugen template)
├─ Tools/      Codegen.c: build-time table generator; LucideSubset.py: icon font subsetter; IconBake.py: app icon sizes; Compare/: side-by-side screenshots against the reference
├─ Tests/      assert-based base, UI, filesystem, jobs, browser and codegen tests (native platform backends, no window code)
└─ Unity.c     application unity root
```

- `function` and `global` expand to `static`. OS headers that use either as an identifier must be included between `#pragma push_macro("name")` / `#undef name` and `#pragma pop_macro("name")`, as `Win/WinPlatform.c` does for `windows.h` (`function`) and `Linux/LinuxWindow.c` does for Wayland (`global`).
- `u64` is `unsigned long` on Linux and `unsigned long long` on Windows. Write 64-bit constants with `UINT64_C(...)`, not a `ULL` suffix, so `_Generic` helpers such as `Min`/`Max` resolve on both platforms.
- Job descriptors are managed on the main thread. Submitting transfers the job arena to the worker; taking completion transfers it back. Adopt result arenas or copy results before releasing a job. Publish only the latest directory generation at a frame boundary.

## Validation

- After logic changes, build with the cheapest useful configuration (`Build.bat` or `./Build.sh`).
- Base-layer changes (arenas, strings, arrays, maps, lists) need their tests in `Source/Tests/Tests.c` updated or extended, then a `test` run on both Windows and Linux (`./Build.sh asan test` in WSL).
- Do not reference spec sections in code comments.

## Workflow

- Commit each finished, validated step right away without asking. If follow-up fixes are requested for that work, amend the commit while it is unpushed.
